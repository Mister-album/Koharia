# LANraragi Review 意见复核与修复（2026-09-10）

## 研判

| 意见 | 实际场景与判断 | 处置 |
|---|---|---|
| P1：网络请求占用进度锁 | 断网/慢网时首次拉取或后台补传持锁，后续阅读事件无法及时落盘；杀进程可能丢待同步记录 | 修复：网络请求移出本地状态锁，网络结果提交前重新核对记录版本、连接会话与恢复轮次 |
| P2：首次显示页漏记 | 单页作品、进入指定页后不翻页、比对完成前退出均可能没有持久化事件；但直接当作新位置上传会覆盖服务端较新进度 | 修复：首次显示即持久化 initialPage 待比对标记；服务端已有不同位置时优先保留服务端。主动翻页、指定页打开和冲突提示中“保留本地”按明确阅读操作处理 |
| P2：合集章节不更新 | 已有章节时，MangaScreen 默认不刷新，因此目录中的新增/重排成员不会反映到已有详情页 | 修复：重开 Tankoubon 时从本地目录同步章节；已有章节 ID 与未读覆盖 memo 保留，不额外逐个请求远端章节来完成成员更新 |
| P2：预览重试无效 | Coil 将重建后的相同请求视为等价，不会重新发起加载 | 修复：按钮调用当前 painter.restart()，保留缓存键 |
| P2：已下载筛选失效 | 原补回逻辑把按分类、标签、状态或合集分组排除的已下载作品再次加入 | 修复：先补充真正不在目录中的下载条目，再统一过滤和分组；无下载的合集不能隐藏已下载独立作品 |
| P2：恢复凭据后沿用旧会话 | 偏好恢复直接写入地址/Key，同 ID、同名来源实例会保留旧 API | 修复：API getter 对照当前地址与凭据，变化时关闭旧会话并重建；不依赖设置页手动 reload |

六项均为真实、可触发问题，因此均修复。第 2 项采用待比对状态，避免违背“打开旧进度页不能直接覆盖较新服务端位置”的既有意图。

## 数据与并发边界

- 新增连续迁移 `18.sqm`，保存首次页待比对标记；普通旧记录默认 false。
- 迁移保留原待同步记录、revision、未读覆盖和阅读时间，兼容 LegacyDatabaseSchemaBridge 预先添加辅助列的情况。
- 本地持久化使用短锁；单独的同步锁防止多个后台补传任务互相覆盖。网络完成后只有对应记录仍未改变才确认结果。
- 用户在网络请求中选择未读或继续翻页时，旧响应不会覆盖新的本地状态。已经发往服务端的请求不能被事务回滚；本地未读覆盖仍按既定规则保持有效。
- 隐身模式保持不记录进度；恢复备份仍禁止把恢复动作当作实际阅读；下载正文和目录缓存不混用。
