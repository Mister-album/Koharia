# PDF 渐进重排

## 交付行为

- 初次打开只等阅读起点所在的 4 页页段准备完成，随后由 Readium 显示；保持小说阅读器界面，不经过漫画阅读器。
- 文本、图片、注释资源按需提供，目录和百分比跳转可请求尚未生成的页段；这些请求优先于后台顺序生成。
- 首屏显示后启动后台生成；阅读交互期间暂缓主动后台推进，但按需读取仍可执行。
- 资源地址和原 PDF 页锚点固定。已完成页段不可变，后台不重写正在打开的首屏 ZIP，也不替换当前正文界面。
- 全书未准备好时只显示原 PDF 阅读百分比，不做全书分页扫描和搜索，也不导出首屏临时包。完整产物生成后开启搜索、完整文件导出及后台分页，准确页数随后更新。
- 原文件获取复用原有连接请求及鉴权；远程 PDF 仍需先取得原文件，当前不包含 HTTP Range 渐进下载。

## 实现与保护

- PDFium 提取支持指定页集合，文档预检及字体基准信息复用；每次处理一段后允许响应新请求。
- 页段构建缓存有限数量的解析结果，避免重复反序列化与版面分析；已压缩 PNG 在 EPUB 中使用 STORED，避免重复压缩。
- 首屏包与完整包分开发布；XHTML、图片、页段标记及完整 ZIP 通过临时文件发布。完整包是可独立使用的 EPUB。
- 活动阅读会话由缓存租约保护。关闭会话取消剩余工作；正常模式保留已完成页段供恢复，无痕模式释放后清理；清理缓存会先停止对应任务。
- 不完整或缺少资源的页段不会作为完整缓存命中；最终完整状态要求所有页段生成并完成打包。
- 缓存版本为 `pdfium-core-2.0.3:ir3:reflow5:epub4`，渐进产物使用独立的 chunks4 键，避免与旧完整转换格式混用。

## 用户手测

1. 打开未缓存 PDF，观察首屏是否明显提前出现。
2. 在后台准备期间跳到远处目录项或拖动百分比，检查目标内容、图片、注释是否正常出现。
3. 持续阅读并等待完成，确认没有突然跳页，准确页数稍后更新。
4. 中途退出再打开，确认位置恢复；完成后再打开应使用完整缓存。
