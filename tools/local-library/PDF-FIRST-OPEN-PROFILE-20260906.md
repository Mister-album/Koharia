# 未缓存 PDF 首次打开耗时分析

> 后续实现与新测量见 `PDF-PROGRESSIVE-REFLOW-20260906.md`；下文为优化前的基线记录。

使用已有 296 页、108,989 字符样本，在模拟器中进行单次分阶段测量。测量不含远程下载、原文件暂存和 WebView 首屏绘制。

| 阶段 | 耗时 |
|---|---:|
| PDFium 提取、图片资源生成和逐页模型落盘 | 5,826 ms |
| 正文结构重建及 EPUB 打包 | 7,019 ms |
| Readium 出版物打开并关闭测量会话 | 128 ms |
| 合计 | 12,973 ms |

提取里程碑：第 1 页 162 ms，第 8 页 1,212 ms，第 16 页 1,487 ms。这些是提取完成时间，不是可见首屏时间。

当前 PdfReflowCacheManager.prepare 必须完成整本提取和 EPUB 打包后才返回；小说阅读器因此一直停在加载状态。仅优化 Readium 初始化无法显著缩短这段等待。

推荐优先引入渐进式首屏：优先处理当前阅读位置所需页，生成可读的初始内容；展示后继续后台转换并按用户翻页需求调整优先级。完成前使用原 PDF 页锚点计算阅读百分比，完成后刷新完整分页结果。已打开的 EPUB ZIP 不应原地修改，应使用独立完成产物及源页／字符锚点进行安全衔接。

第二优先级是减少重建阶段的重复逐页反序列化、重复版面分析、字体信息查询与已压缩图片的重复压缩。导入后的空闲预处理可以作为补充，但不能替代首次打开的渐进加载。

本轮只增加分阶段测量并完成自动测试，未实施渐进式转换，也未操作实机界面。证据：`artifacts/pdf-first-open-profile-20260906/`。
