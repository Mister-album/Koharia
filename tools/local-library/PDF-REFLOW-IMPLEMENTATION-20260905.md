# PDF 重排首版实施与验证（2026-09-05）

## 交付范围

按 `PDF-REFLOW-READIUM-PLAN-20260905.md` 实施首个可用版本：保留原版 PDF；新增 PDFium → 逐页结构模型 → 带样式的 XHTML／派生 EPUB → 现有 Readium。当前是手动开启的首版，不代表 P3 和后续复杂排版能力全部完成。

- 原版 PDF 位图先填充不透明白色，解决黑色阅读器背景下透明纸面与黑字叠加的问题。
- 现有页面加载器有原始 PDF 文件时，“更多选项”显示“重排阅读”；Readium 的“更多”提供“原版 PDF”。仅有服务器页图时不显示转换入口。
- 固定 `io.legere:pdfiumandroid-core:2.0.3`。Kotlin 适配器隔离并串行管理原生对象；小型 JNI 桥复用同一 `libpdfium.so`，补充字形字体、字号、字重、颜色、坐标和图形对象信息。许可证随 APK 打包。
- 普通单栏横排重建段落、相对字号、基本强调与颜色、章节目录和插图。正文基础字号沿用现有 Readium 设置，当前实机为 16；原 PDF 的点数不直接作为屏幕字号。
- 注音、旋转、图文重叠、多栏信号等低置信度页面保留原页图。无可靠文字层的文档转换失败时留在原版。
- 原页、字形范围、区域、上下文与 XHTML 锚点保存在映射中。原文件指纹和转换版本决定缓存修订号；本地保存原 PDF 页号及 Readium 定位，版本改变时尝试上下文和字符位置恢复，再回落原页。
- 转换缓存独立于手动下载和 EPUB 原书缓存，含容量限制、取消清理、活动会话租约、无痕临时产物与统一临时缓存清理入口。

## 测试中修复的问题

1. 中文标点的字形框较低，按字形高度分行会拆散同一行，产生错误的多栏判定和标点顺序。改用字体 em 大小计算容差，并增加回归用例。
2. 日文注音需要与下方汉字关联；普通分行无法正确表达语义。首版识别这一信号并保留原页图，后续再实现 XHTML ruby。
3. Readium 一屏可能包含原 PDF 前一页末尾和目标页；进入位置仍可见时优先用进入锚点，避免立即返回原版时被屏幕顶部的前页文字带偏。

## 验证证据

- `spotlessApply`、`spotlessCheck`、`:app:compileDebugKotlin`、`:app:assembleDebug`、`:app:assembleDebugAndroidTest` 通过。
- PDF、EPUB 和页面加载器相关单元测试共 127 项通过。
- Android 17、x86_64、16 KB 页大小模拟器上的 4 项设备测试通过：原版白纸、样式和插图提取并由 Readium 打开、缓存租约与无痕释放、真实 296 页文件转换。
- 当前用户样本：296 页、PDFium 提取 108,989 个字符；最终转换测试约 12.4 秒（模拟器单次测量，不是性能承诺）。275 页正文重排，21 页保留原页图。`audit-pdf-reflow.py` 检查重排正文与文字层正文顺序一致、锚点无重复、EPUB ZIP 和 XHTML 可解析。
- 内容核对忽略空白并单独排除页边区域；不是对扫描图像进行 OCR 对照，也不代表所有 PDF 的语义读取顺序都正确。
- ARM64、x86_64 的三个相关原生库全部满足 16 KB ELF LOAD 对齐；32 位库为 4 KB。实机 Xiaomi 2106118C / Android 16 已安装调试版并验证入口、转换、主题、字号 16→17→16、取消后原版仍可读。
- 修正进入锚点后，实机最终往返为原版 161–162 / 296 → Readium → 原版 161–162 / 296；缓存重新打开可直接进入 Readium。没有把重排后的 262 个视觉页数写回原 PDF 总页数。
- 日志、截图、内容审计和 ABI 记录在 `artifacts/pdf-reflow-implementation/`。真实用户 PDF 与转换产物仅用于本地验证，没有加入测试资源或提交。
