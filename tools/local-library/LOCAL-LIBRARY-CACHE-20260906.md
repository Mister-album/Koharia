# 本地书架缓存浏览与首次加载状态

## 原因

书架先得到零条目的初始分页状态，随后才收到数据库及索引结果。页面仅在扫描时显示加载状态，把分页尚未完成的零条目当成了空书库。此外，静态 `PagingData.from()` 没有显式报告完成状态，不能仅通过增加 Loading 判断修复。

原书架还在初始化时检查是否需要扫描，并在进度统计缺少总页数时打开文档计算页数。这些动作不适合仅浏览缓存的使用方式。

## 当前行为

- 进入、切换、返回本地书架只根据已有扫描索引和数据库构建列表，不检查是否需要自动扫描，也不自动补扫空缓存。
- 下拉刷新或菜单刷新才由书架主动扫描目录；刷新已有内容时保留旧列表。
- 分页首次加载显示加载状态，静态数据提交时显式报告加载完成；真正的空缓存提示用户手动扫描。
- 阅读统计只使用数据库中保存的章节、小说进度及总页数。缺少总页数时不打开文档计算；旧版 URL 的进度索引匹配也只使用缓存，不解析文件路径是否存在。
- 用户通过应用执行导入、删除、移动或标记等操作时，仍保留这些操作自身的索引／数据库更新。外部新增或删除文件不会因打开书架被自动发现，需要手动刷新。

## 验证

- `spotlessApply`、`spotlessCheck`、`:app:compileDebugKotlin`、`:app:assembleDebug` 通过。
- 66 项本地库单元测试通过，包括 5 项状态回归：数据库首次结果延迟、缓存展示与仅手动扫描、手动扫描失败、真正空缓存、阅读统计不打开文档。
- 已覆盖安装至实机 `3ef7b819`，保留应用数据。
- 日志：`artifacts/local-library-cache-build.log`、`artifacts/local-library-cache-install-physical.log`。
